Extraction QA viewer — three sample screens

A mockup of the workflow described earlier: overlay ground truth against what the pipeline extracted, drill into why mentions did or didn't cluster together at a given resolution threshold, and correct a ground-truth label — with a field guide and a click-to-set boundary picker — without touching the sealed manifest by hand. The slider, match-lineage tables, and boundary picker below run on client-side JS against small canned examples; everything else is a picture of the intended interaction, not a live view over a real run.

None of this reads real pipeline output. Sample doc text, spans, scores, and cluster memberships below are illustrative, written to match the shapes described in ARCHITECTURE.md — not pulled from data/ground_truth or store/. Nothing here is published anywhere; it is a local file for review before any of it gets built.

Screen 3 of 3

Correcting a ground-truth label

Clicking a flagged span from Screen 1 opens this form instead of editing the manifest by hand. A field guide on the left explains what each field means before you fill it in; a click-to-set boundary picker on the right shows every word's exact character offsets so you never have to count them by hand. Submissions append to data/gt_corrections.json — a patch file audit.py applies at read time. The sealed manifest itself is never touched, so corpus_gen.py + seed still regenerates the exact same base file.

qa_viewer.py — correct ground truth

Field guide

span kind
entity — a person or org mention. identifier — address / phone / email / NPI / TIN / SSN / VIN. event — a dated action (filed, scheduled, paid…). non_entity — a planted look-alike that should stay untagged; it tests precision, not recall.
entity_class
person or organization — nothing else. Role (attorney, claimant, medical_provider, repair_shop, adjuster) is a separate field, don't conflate them.
gt_entity_id
Reuse the existing ID if this mention belongs to an entity already in the manifest — search by name first. Only mint a new gt_eNNNNN if it's genuinely new, and double-check: ground truth is meant to be generator-derived, not hand-authored piecemeal.

hard_case_tags (attach any that apply)

jr_sr
Jr/Sr suffix conflict at the same address.
phoenix_shop
Repair shop reopened under a new name at an old address.
shared_address
Two distinct entities share one address.
recycled_phone
A phone number reassigned to a different entity later.
address_change
This entity's address changed over time.
identifier_reassigned
An identifier moved from one entity to another.
high_fanout
Entity recurs across an unusually large number of claims.
cross_occurrence
Entity appears across more than one occurrence.

orphan (identifiers only)

Check this when no name is co-located with the identifier mention — it's the case identifier-first resolution exists to handle.
