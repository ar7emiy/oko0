OFFLINE · READER-FIRST · FICTIONAL TRAINING CLAIM

Annotate the notes. The application creates the dataset.

You never need to inspect an Excel row while you work. Select evidence in the complete note, make one short annotation decision, and the application records the source location and creates the workbook data behind the scenes.

Your only job

  1. Read every note in the claim.
  2. Select exact wording that identifies an entity, refers back to one, states a field, describes an entity, or states an action or relationship.
  3. Choose the appropriate action.
  4. Mark each note read when you have finished it.

The application handles claim IDs, note IDs, UTF-8 character offsets, entity references, output rows, saving, and the Excel export. The note text is locked so it cannot be changed by mistake. You do not need a category or subcategory list.

1. Load the packet and read the note

  1. Click Load notes and select every note text file for the claim.
  2. Choose the claim and note from the two selectors.
  3. Read the complete note in the centre panel.
  4. When you finish the whole note, check I have read this whole note.
  5. Use Load client output only to prepare later reconciliation. It stays hidden during Gold work.
Do not start with a spreadsheet, a client row, a category, or a similarity score. Start with the note text.

2. Create or link an entity

Select the highlighted wording, then click one button. Click the phrases below to see the intended action.

Maya Chen called. She said Elena Ruiz of Harbor Legal represents her.
Click a phrase. The app action appears here.

The reader actions

New entity creates one local entity and a named source mention.

Link reference connects a pronoun, alias, repeated name, or description to an existing local entity.

Record field captures an observed address, TIN, phone, or other record value.

Record context keeps exact descriptive wording linked to an entity; it has no mandatory category or subcategory.

Record statement keeps the exact wording of an action or relationship, plus its primary entity and an optional second entity.

Mark uncertain preserves unresolved text without forcing a guess.

“She” and “her” are not skipped. Link each to Maya Chen. That creates the coreference evidence automatically.

3. Capture entity fields directly from note evidence

Select only the exact value, then click Record field value. Associate it with the entity and choose the field name. The app stores the value, note ID, exact text, and character offsets automatically.

The Harbor Legal contact record lists 10 Bay Street, Exampleton, IL 00000, telephone 555-0101, and TIN TRAINING-001.
Click a value. The correct field action will appear here.

One selected value produces one independent field assertion. That gives you a true Gold record for name, address, city, state, ZIP, phone, and TIN when the note states them.

When a value is absent, do not infer it. When it is unclear, select the relevant text and use Mark uncertain.

4. Finish reading, then seal Gold before client comparison

  1. Read every note and finish entity, reference, and field annotation.
  2. Check I have read this whole note for every note. The app will not seal while one is unfinished.
  3. Use Undo last change to correct the most recent action. Every action is also automatically saved beside the notes; use Restore saved work after a restart.
  4. Click Seal this claim.
  5. Only now enable Show client proposals after sealing.
  6. If a flagged watchlist record explicitly cites the current reviewed note, the app opens a watchlist-review window. Compare the system entity and the watchlist candidate with the source note still visible, choose a decision, and explain it.
  7. Export the workbook whenever you need a checkpoint.
The client output is useful after Gold is sealed: it can be reconciled against independent names, fields, and coreference links. It is not the material the reviewer uses to create Gold.

The export includes the Gold mentions, Gold entity fields, coreference links, uncertain spans, raw client output, watchlist decisions, and the shared Plan B review tabs. The reviewer does not need to open the workbook to verify that their actions were saved.
