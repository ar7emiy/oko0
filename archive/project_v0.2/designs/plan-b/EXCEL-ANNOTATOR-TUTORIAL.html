How to complete the Excel review workbook

Use the note-text packet as the evidence. This page is a guided practice claim: click the highlighted words, see why they matter, then see the exact worksheet row you would complete.

What the coordinator gives you

  • A complete note-text packet for each claim, for example C104_N01.txt and C104_N02.txt.
  • One joined Excel workbook. Filter it by claim_number; use note_id to open the right text file.
  • This read-only tutorial. It does not collect answers. Your decisions are saved in Excel.

There are two human workflows: for a claim chosen for blind gold, annotate the note packet before seeing client outputs. For an assisted claim, start from the immutable client row, then verify it against the complete notes. Both use the same local entity references and mention/coreference structure.

1. Read every note before deciding what a reference means

Click each highlighted phrase. A named phrase, a pronoun, and a description can all refer to the same local entity, but each is a separate source mention.

C104_N01.txt · note N01

Maya Chen called. She said Elena Ruiz of Harbor Legal represents her.

C104_N02.txt · note N02

Harbor Legal emailed Maya Chen. Harbor Legal requested a reply. The firm asked Elena Ruiz to respond.
Click a highlighted reference.
It will explain the local entity link and why the wording belongs in the workbook.
Do not collapse source mentions: N02 has two literal “Harbor Legal” passages plus “The firm.” All three support one organization, but they are three traceable locations.

2. Assisted review: inspect a client row against the notes

Use this path for the wider assisted dataset. In 01_Raw_client_output, filter to the claim. The raw row stays unchanged. Its recordType tells you where the proposal came from; it does not create a separate entity population.

Step 2A — start at the supplied note ID, then read context

N02: Harbor Legal emailed Maya Chen. Harbor Legal requested a reply. The firm asked Elena Ruiz to respond.
Click a highlighted phrase. The relevant raw and review rows will be highlighted.

Step 2B — keep one local entity reference

CR1 and CR2 both support E1, Harbor Legal. The fact that one row is entity and another is exact_search does not create E1 and E2.

Step 2C — validate every populated record field

In 04_Entity_field_review, add one row for each nonblank name, address, city, state, ZIP, phone, and TIN value. Capture the proposed value, exact source wording, note ID, source-match method, decision, and corrected value when needed.

Step 2D — test classification separately

In 05_Category_review, the client’s legal / law_firm / ORG values are proposals. Mark each as supported, contradicted, ambiguous, or not_assessable from note context. “The firm” supports organization context here; it does not make every category automatically supported.

Exact-search rows without positions: do not assign CR1 to the first phrase and CR2 to the second merely because of row order. If the input has no position, record the supported source wording and explain the ambiguity. Do not invent provenance.

3. Blind gold: create independent claim evidence

Use this path only for the sampled blind-gold claims. Start with the note files and 07_Blind_gold_mentions. Do not open 01_Raw_client_output, category proposals, or watchlist data for that claim until this work is complete.

Step 3A — enter one mention at a time

N01: Maya Chen called. She said Elena Ruiz of Harbor Legal represents her.
N02: Harbor Legal emailed Maya Chen. Harbor Legal requested a reply. The firm asked Elena Ruiz to respond.
Click a phrase above. It will highlight the row you enter in 07_Blind_gold_mentions.

Step 3B — reuse the local entity reference

Use one local reference for all mentions of the same entity: E1 Harbor Legal, E2 Elena Ruiz, E3 Maya Chen. A local reference describes this claim only. It is not a cross-claim identity decision.

What gold measures: it provides independent named mentions, entity grouping, coreference links, and observed entity fields in 08_Blind_gold_entity_fields. It can reveal a client result that has no gold counterpart and a gold entity that client output missed.

4. Review each returned high-score watchlist pair

For Phase 1, filter to Entity_Watchlist_flag = 1 and GenAI_tok_sort_similarity > 90. Inspect the system entity in its complete claim context before deciding whether it is the same real-world entity as the watchlist record.

Step 4B — enter one pair decision

In 09_Phase1_pair_review, record same_entity, different_entity, insufficient_evidence, or needs_context; also record source support and decisive facts. 10_Phase1_summary calculates precision for determinate completed reviews only.
