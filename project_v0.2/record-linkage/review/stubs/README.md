# SME review packet: stub (fictional)

Everything here is generated by `b2_build_stubs` in `../../b2_sections.py` from the pipeline's
**synthetic** run (seed 20260926): every name, identifier and address is fictional. It shows
exactly what a review round looks like; a real round is written by `b2_run` into the gitignored
`review/<dataset>/<run_id>/round_NN/` with the same layout. Regenerate with
`RL_B2_WRITE_STUBS=1 python b2_sections.py` (byte-identical on rerun).

| Folder | Who gets it | Files |
|---|---|---|
| `to-annotators/A1/`, `A2/` | one SME each | `review-workbook_<id>_round00.xlsx` (sheets Instructions, Persons, Businesses, Data dictionary), `SME-INSTRUCTIONS.md`, `data-dictionary.csv`, `labels-template_<id>_round00.csv` |
| `to-adjudicator/` | the adjudicator, after labels return | `adjudication_round00.xlsx`: pairs the SMEs disagreed on or marked unsure, their labels and reasons (as Reviewer 1 / 2), cells for the final label |
| `coordinator/` | the study coordinator only | `sample-key_round00.csv` (hidden: stratum, p and basis at sampling, N_h, n_h, inclusion probability, weight, split, seed), `assignments_round00.csv`, `pair-queue-import_round00.csv` (blind flat file for an app's review queue), `label-schema.csv`, `packet-manifest_round00.json` (counts and SHA-256 of every file) |
| `examples/` | training and QA | the same workbooks and CSVs with labels filled in by simulated SMEs (`*_FILLED`), the filled adjudication sheet, the resulting `final-labels_round00_EXAMPLE.csv` and `agreement_round00_EXAMPLE.csv` |

**What an SME sees**: one row per pair, the extracted record's values beside the watchlist
record's (name, date of birth, identifiers, licence, specialty, category, address, phones,
email, vehicle, and the other party on the same input row), an opaque `review_id`, and
drop-downs for `label` (match / non-match / unsure) and `confidence` (high / medium / low), a
`reason` cell and a date. No score, basis, bits, stratum, split or record id. Data cells are
locked; double-coded pairs appear in both SMEs' files in different orders.

The round has 63 pairs (at most 3 per stratum so the stub stays readable); every `sealed_test`
and `calibration` pair and about a third of the others go to both SMEs; 7 pairs went to
adjudication in the example.
