Extraction QA viewer — three sample screens

A mockup of the workflow described earlier: overlay ground truth against what the pipeline extracted, drill into how mentions cluster into entities at a given resolution threshold, and correct a ground-truth label without touching the sealed manifest. Static, with the threshold slider and correction queue wired up in client-side JS against canned sample data — everything else is a picture of the intended interaction, not a live view over a real run.

None of this reads real pipeline output. Sample doc text, spans, and cluster memberships below are illustrative, written to match the shapes described in ARCHITECTURE.md — not pulled from data/ground_truth or store/. Nothing here is published anywhere; it is a local file for review before any of it gets built.

Document overlay — extraction vs. ground truth

One note, two highlight layers merged into one. Green = the extractor found what ground truth planted (true positive). Red wavy = ground truth planted it and nothing matched (miss). Amber = the extractor found something ground truth didn't plant there (false positive).
