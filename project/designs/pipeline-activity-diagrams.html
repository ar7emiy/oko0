How a raw note becomes a resolved entity

Six UML activity diagrams covering the identification and metadata-linkage pipeline end to end, each with the real data going in and coming out of every step. Node subtitles name the actual function that does the work, so a diagram and the code can be read against each other.

A Freeze and fingerprint the note

single goal of this blockMake the note's exact bytes tamper-evident, so every character offset recorded later stays meaningful.

Worked data example

data going indata coming outwhat happened
Spoke with Robert Miller regarding the POA update filed last week. He confirmed…
note_0734.txt · 2,317 bytes		"note_0734": "a3f1c9e2b7d4…8e1f"
64 hex chars, in data/hashes.json		The whole file collapses to one fixed-length digest, so a single changed character produces a different digest and is caught on the next verify.

D Extract candidates, filter, and persist

single goal of this blockTurn chunk text into typed, span-grounded rows: mentions, identifier observations, assertions, coreference links.

Worked data example

data going indata coming outwhat happened
…transfer note. Contacted James Moore per yesterday's…
chunk text → token NER		SpanCandidate{start: 812, end: 823, text: "James Moore", label: "person", score: 0.75}The capitalized-run regex first matched "Contacted James Moore"; the trimming pass stripped the sentence-opening verb while keeping the offsets byte-exact.
…callback left at (312) 555-0148, no name given…
chunk text → gazetteer		GazetteerHit{start: 918, end: 932, text: "(312) 555-0148", label: "phone", valid: true}A pattern match plus structural validation turns a run of characters into a typed identifier hit that carries its own provenance.
Dr. Alicia Reyes (NPI 1568291037) confirmed the claimant remains under care.
chunk text → LLM pass		Assertion{subject_mention_id: "m0000153", predicate: "has_npi", object_value_raw: "1568291037", object_value_norm: "1568291037", polarity: "asserted", source_span_start: 1204, source_span_end: 1214, confidence: 0.9}The model reads one sentence and emits a subject–predicate–object triple whose evidence span points back at the exact characters it was drawn from — the triple is rejected if that span doesn't re-ground.
SpanCandidate{text: "Jones", label: "person"}dropped · n_dropped_shape += 1A single-token surname fails the two-capitalized-token shape filter and never becomes a mention — a known, measured recall gap rather than a silent one.
GazetteerHit{text: "(312) 555-0148"} with no name inside the proximity windowidentifier_observations{kind: "phone", value_norm: "3125550148", subject_mention_id: NULL}With no name nearby, the identifier is still recorded and the subject left null — this is the case that identifier-first resolution exists to serve, and dropping it here was the original 0%-orphan-recall bug.

— Out of scope here, and what's queued next

These six diagrams stop where identity and linkage are established. Query-time retrieval (Layer 4 — claim-filtered chunk search plus cross-claim entity enrichment) is deliberately not drawn: it consumes this output rather than producing it, and mixing the two makes both harder to read.
